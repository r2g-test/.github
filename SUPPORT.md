# Support

## Getting help

Use the affected repository's issue tracker for reproducible bugs, documentation gaps, and narrowly scoped feature requests. Include the repository version or commit, operating environment, commands run, expected result, actual result, and a minimal reproduction when possible.

Use GitHub Discussions when enabled for open-ended questions, design exploration, or community help that is not yet an actionable issue.

## Not appropriate for public support

Do not post credentials, personal data, private logs, embargoed vulnerability details, or access requests in public issues. Follow `SECURITY.md` for vulnerabilities and use the organization's approved private channels for account or permission problems.

## Response expectations

Repositories are maintained according to their documented maturity and priority. Acknowledgement and resolution times are best-effort unless a separate service agreement applies. Maintainers may close incomplete, duplicate, out-of-scope, or irreproducible reports after explaining what information or next step is needed.
